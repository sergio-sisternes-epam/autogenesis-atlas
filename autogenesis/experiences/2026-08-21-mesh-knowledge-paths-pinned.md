## What happened

## One-line rule

**Mesh = explicit knowledge→knowledge navigation paths between stores. No default mount of all brains. Read/write on project and package; mesh only by following declared knowledge links under hop/effort limits.**

## Details

| Rule | Meaning |
|------|---------|
| **Not a mount** | Do not union-mount every available agent/skill wiki by default |
| **Edge = navigation** | Durable dependency is a typed/declared path from knowledge (or index) in store A to **knowledge/index** in store B |
| **Cite vs edge** | One-off links are cites; durable “needs X behaviour” should be an explicit mesh edge for hop policy and scope |
| **Read/write plane** | Normal R/W on **project** and **package** only |
| **Expand** | Follow mesh knowledge links when needed (think-effort hops: low 1 / balanced 3 / high 5 / deep 10) |
| **Cross-store** | knowledge → knowledge only — **never** foreign raw |
| **Write isolation** | Following a path does not grant write into the peer package; writes stay on active project write-root |

## Example (terraform → okf-wiki)

- terraform needs experience-building behaviour → knowledge path to okf-wiki index/procedure knowledge  
- Optional shortcut to a specific okf-wiki module knowledge node  
- Progressive disclosure along the path — not a full okf-wiki dump  
- Evidence changes under okf-wiki stay local; terraform re-judges via knowledge updates

## Defaults (contamination control)

- **Deny-by-default mount** (no ambient full mesh)  
- Edges created when a real dependency is known (not silent interconnect of all skills)  
- Owner/context-gated edge creation preferred over automatic fan-out
