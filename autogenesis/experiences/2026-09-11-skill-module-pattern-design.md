# Skill Module pattern design

The user explicitly requested: "Let's shape that as new pattern under the
genesis discipline, hosted inside autogenesis." This authorises formal design,
not automatic implementation or active-pattern admission.

Read the installed Autogenesis design/workflow/patterns/challenge procedures,
loaded Genesis and OKF, and reused the existing resolved subject Atlas.
Compared the proposal with Genesis S1, S3, C1, B2 and refactor triggers; fetched
the live Agent Skills specification and description guidance.

Important finding: Genesis already uses "module" for a distribution unit.
The proposal therefore uses the qualified name **Parent-routed Skill Module**
for private procedures within one distribution. The new pattern is a
constrained structural extension, not an assertion that modularity or lazy
loading is novel. Proposed display S8 is scoped to Autogenesis, not reserved
in the upstream catalogue.

Proposed pins: draft first; no independent exports, versions or implicit
threads; parent context ownership; one referenced invocation authority;
module/invocation/card/receipt separation; no decomposition without need.
B17 stays active. No claim of new host-discovery proof or independent repeated
adoption follows from the existing 21-module implementation.

The packet includes component, sequence and dependency diagrams, catalogue
delta, applicability, integration scope, cost bounds, full new happy/adversarial
scenario drafts, three paired task evaluations and 20 split selection queries.
Agent-spec is unavailable, so no Gherkin or b- IDs were invented. Evaluations
are planned, not run. One coordinator handled this bounded design; no extra
agents or pricing/savings claims.
