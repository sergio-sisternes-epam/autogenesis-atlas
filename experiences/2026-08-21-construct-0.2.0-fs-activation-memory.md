## What changed

- **FS activation monitor** is mandatory on construct workspaces.
- Backend pin: **watchdog** (inotify) → ctypes → poll; never require `inotifywait` CLI.
- Events: `<workspace>/activation.jsonl` with `source: fs`, kinds skill|path|module|knowledge|raw.
- Lifecycle: start on `create`, stop on `destroy`.
- Smokes: `type: activation-log`; train-report H1 ties reevaluate to FS path event when log present.
- Scenario **train-docker-mesh-v1 v3**: dead knowledge-crawl edge removed; activation-fs smoke added.
- Versions: construct **0.2.0**, agent-brain **0.3.3**.
- Manual `log-activation` is **not** FS proof.

## Why

Docker train v2 passed self-reported skills and narrative path audits. User required deterministic capture of skill, subskill/path, okf-wiki module, and knowledge activation via **filesystem monitoring**.

## Proven
